# 库存查询、流水复核与跨仓协同指南

## 查询当前库存

查询某仓某商品的实时库存时，必须提供至少以下参数：

- `warehouse_id`：目标仓库编号
- `item_id`：商品 SKU

优先调用 `inventory_query` 工具，返回字段包括：

- `on_hand`：总在库
- `available`：可用库存（已扣除占用）
- `reserved`：订单占用库存
- `damaged` / `quarantine`：残次或隔离库存

查询结果应一并给出商品规格、批次、最近流水时间，便于进一步追溯。

## 查询库存流水

当用户需要判断库存波动原因、出入库明细或异常来源时，应调用 `inventory_log_query`：

- 必填 `warehouse_id` 和 `item_id`
- `days` 建议控制在 **7-30 天**，超长窗口仅用于复盘而非高频问答
- 支持按 `source_type` 过滤：`inbound` / `outbound` / `transfer` / `adjust` / `return`
- 流水条数超过 500 时应分页返回，不允许一次性拉全量

## 标准复核顺序

1. 先看当前库存快照，确认 `on_hand`、`available`、`reserved` 三项是否自洽
2. 再查近 N 天流水，核对入库、出库、调拨、冲正的发生时间和金额
3. 对照订单占用情况，确认 `reserved` 是否对应真实订单
4. 如果库存快照和流水累计结论冲突，**标记为待人工排查**，不得自作解释
5. 结论输出时引用具体流水 ID 和发生时间，不要模糊描述

## 跨仓库存与调拨查询

- 跨仓调拨涉及两个 `warehouse_id`（源仓和目标仓）
- 调拨单状态分为：`created` / `in_transit` / `received` / `cancelled`
- 源仓流水体现为 `transfer_out`，目标仓流水体现为 `transfer_in`
- 调拨途中（in_transit）的库存既不计入源仓 available 也不计入目标仓 available
- 查询跨仓库存时，应明确调拨途中的数量，避免客户误以为"库存消失"

## 盘点与对账

- 盘点记录通过 `source_type=cycle_count` 的流水体现
- 盘盈盘亏会触发 `adjust` 类流水，必须关联盘点单号
- 每月末和季度末是高频对账期，应优先响应仓管的对账请求
- 库存快照与总账差异超过 **1%** 时，视为对账异常
- 对账异常应回溯最近 30 天的 `adjust` 和 `transfer` 流水，找出具体偏差来源

## 批次与效期

- 部分商品（辅料、胶水、美缝剂）按批次管理，带 `batch_no` 和 `produce_date`
- 效期管理商品按 FEFO（先到期先出库）排序
- 查询时可指定 `batch_no` 获得该批次的专属库存
- 接近效期（剩余 < 60 天）的批次应优先出库或提示促销

## 权限边界

- 只能查询当前角色权限范围内的仓库与商品
- 不得向无权限用户暴露他仓库存或敏感流水
- `customer` 角色无法查询任何仓库详情，所有仓储字段不得回传客户端
- 跨仓查询需要仓库管理员或 admin 角色，普通 staff 默认只能查本仓

## 回答边界

- 具体数量、规格、流水请直接引用工具返回字段，不得推测或拼凑
- 用户没提供 `warehouse_id` 或 `item_id` 时，必须先追问再调工具
- 流水数据用于辅助判断，不能替代人工盘点结论
- 涉及高风险推断（如"是不是被盗"），应提示人工介入而非直接下结论
