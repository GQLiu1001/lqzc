# 高风险出库审批完整规范

## 触发审批的场景

以下仓储动作默认进入审批链路，由 `outbound_apply` 工具触发 interrupt：

- Agent 发起的所有出库申请
- 单笔数量超过 **500 件** 或金额超过 **10 万元** 的大批量出库
- 发生在非工作时段（22:00 - 次日 08:00）的出库申请
- 涉及敏感商品：岩板大板、保税商品、样板展示品
- 已有未结审批或近 7 天存在被驳回记录的仓库-商品组合
- 库存波动异常、近期有冲正或人工修正关联的出库

## 提交前必须具备的参数

- `warehouse_id`：出库仓库
- `item_id`：商品 SKU
- `qty`：出库数量，整数，不允许负数和零
- `reason` 建议一并提供，便于审批人判断业务背景
- `target` 如果涉及调拨或内部使用，应提供目标仓库或部门

缺少核心参数时，Agent 必须先追问，**不能直接提交审批单**。

## 风险分级与审批人

- **低风险**：数量 < 100 件、金额 < 1 万，`warehouse_manager` 可单人审批
- **中风险**：数量 100-500 件 或 金额 1-10 万，需要双人审批
- **高风险**：数量 > 500 件 或 金额 > 10 万，需 `admin` + 仓库主管联审
- **极高风险**：单笔 > 1000 件 或 金额 > 50 万，除联审外需要业务 VP 书面确认

## 角色边界

- `staff`：可以发起申请、查询状态，不能审批
- `warehouse_manager`：可以发起和审批中低风险申请，不能自审自批
- `admin`：可以通过 `/chat/interrupt/decision` 执行 `approve` 或 `reject`
- 非仓储角色不得绕过权限直接触发审批工具
- 审批人和申请人必须是不同账号，系统会拒绝自审请求

## 审批与执行关系

- 提交 `outbound_apply` 后，系统生成待审批申请并返回 `need_approval`
- `approve` 代表允许继续执行后续出库动作，但仍需走正式的仓库作业流程
- `reject` 终止本次审批申请，不会自动扣库存、不会继续执行出库
- 审批通过后的实际出库仍需经过 WMS 人工确认或二次校验
- 系统不允许 Agent 直接改库存，所有动作都走 WMS 标准接口

## 审批 SLA 与升级

- 低风险审批：首次响应 **4 小时**，超时自动升级到双人审批
- 中风险审批：首次响应 **2 小时**，超时升级到 admin
- 高风险审批：首次响应 **1 小时**，超时直接进入应急联审
- 极高风险审批：首次响应 **30 分钟**，超时自动通知值班主管和 VP
- 审批超时默认视为搁置，不会自动 approve 或 reject

## 幂等与重复提交

- 系统基于 `sessionId + tool + business_key` 生成 `idempotency_key`
- `business_key` 由 `warehouse_id + item_id + qty + date` 哈希得到
- 同一会话短时间内重复提交相同参数，视为同一审批请求并去重
- 幂等命中时返回已有审批结果或当前状态，不新建审批单
- 跨会话或跨日的相同申请不适用幂等，会视为新申请

## 驳回与重新提交

- `reject` 通常附带 `comment`，说明驳回理由
- 申请人可根据驳回原因调整参数后重新提交
- 连续 3 次被同一审批人驳回的组合，系统标记为黄标，需要 admin 介入
- 黄标申请即使参数合法也会被自动暂停，由业务主管人工判定

## 日志与审计

- 所有审批动作（apply/approve/reject）落 `audit_log` 表
- 审计字段包括操作人、时间戳、session_id、参数摘要、决策和理由
- 审计记录保留至少 **5 年**，对接合规审查
- 禁止以任何方式修改或删除历史审计记录

## 回答边界

- 审批状态、待办申请数量、具体决策人由审批工具查询，不得口头承诺
- 涉及合规风险的申请，必须走人工判断，不允许 Agent 自动决策
- 一旦 interrupt 触发，Agent 必须等待 `/chat/interrupt/decision`，不得伪造通过
